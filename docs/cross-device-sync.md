# 기기 간 학습 기록 동기화

휴대폰과 PC에서 같은 계정으로 로그인하면 서버의 계정별 학습 기록을 사용한다. 비로그인 기록은 해당 브라우저에만 남는다. 이 수정은 기출 풀이, 오답, 북마크, 응시 이력과 전공노트 완료 기록을 다룬다. 기술면접 준비의 자가 점검 완료 표시는 기존처럼 브라우저 저장 방식이다.

## 확인한 결함과 변경

- 같은 계정인데 연결 실패나 서버 실패가 표시된다는 제보에 맞춰, 기록 조회의 네트워크 오류와 일시적인 5xx 응답을 최대 두 번 재시도한다. 429 요청 제한은 서버가 보낸 Retry-After 대기시간을 지킨다. 전체 조회 대기 예산은 기존 90초 안에서 사용하며 401 등 인증 실패는 재시도하지 않는다. 실제 운영 서버 오류의 원인은 운영 로그 접근이 없어 확정하지 않았다.

- 기존 저장 실패 처리는 메모리 대기열에만 기록을 되돌렸고 자동 재시도와 새로고침 후 복구가 없었다. 이제 계정별 대기열을 localStorage에도 남기고 일시적 실패 시 재시도하며 로그인, 온라인 복귀, 창 복귀 때 복원한다. 페이지가 숨겨지거나 닫힐 때도 대기 중인 전송을 시작한다. 종료 중 네트워크 전송 완료 자체는 브라우저가 보장하지 않으므로 미확인 기록은 다음 접속까지 보관한다.
- 같은 문제집의 저장 요청을 겹쳐 보내면 이전 요청이 나중에 완료될 수 있었다. 문제집별로 전송을 직렬화하고 대기 중에는 최신 로컬 상태를 보관한다.
- 대기열이 전송 시점의 로그인 토큰을 사용했다. 이제 요청마다 기록 소유 계정과 토큰을 고정한다. 이전 계정의 늦은 401 응답은 현재 계정을 로그아웃시키지 않는다.
- 풀이 화면은 문제집을 처음 열 때만 원격 기록을 읽었다. 로그인, 재연결, 창 복귀와 보이는 화면의 30초 간격에서 다시 합친다. 원격 요청 도중 로컬에서 푼 답도 화면에 유지한다.
- 서버는 마지막으로 도착한 스냅샷 전체로 기존 데이터를 교체했다. 이제 사용자 행을 잠가 첫 저장부터 같은 계정의 쓰기를 직렬화하고, 문제별 `stats`, 북마크 `marks`, 노트 `completed`는 항목별 `at` 시각으로 합친다. 해제 상태도 기록으로 보존한다. 응시 이력은 중복을 제거한 최신 200건을 유지한다. 누락된 다른 기기의 항목은 삭제하지 않는다.
- 전공노트 완료 체크는 서버 조회 후에 로컬에 적용했다. 이제 클릭을 먼저 로컬에 보관해 조회 실패 후에도 재시도로 저장할 수 있다.
- 홈의 전체 기록 동기화는 실패해도 10분 대기 시각을 먼저 남겼다. 이제 계정별로 관리하고 성공한 뒤에만 시각을 갱신한다.

수동 동기화는 업로드에 실패했을 때 성공했다고 표시하지 않는다. 기존 계정 인증, 본인 기록 접근 제한, 티어 계산과 비공개 배지는 유지한다.

## 충돌과 범위

같은 문항을 여러 기기에서 수정하면 더 큰 `at` 값을 가진 상태를 사용한다. 같은 시각은 먼저 저장된 값을 유지한다. 두 기기에서 동시에 같은 문제를 푼 횟수를 이벤트 단위로 정확히 합산하는 방식은 아니다. 기기 시계가 크게 어긋나면 최신 상태 판정에도 영향을 줄 수 있다.

기존 브라우저 단위의 비로그인 풀이 캐시와 백업 병합 정책은 바꾸지 않는다. 실패 기록의 지속 보관은 브라우저 저장소가 사용 가능하고 지워지지 않았다는 조건이 필요하다. 코드와 가상 계정으로 결함을 재현한 결과이며 실제 제보자의 기기나 운영 DB를 조사한 결과는 아니다.

## 검증

```bash
cd frontend
npm run check:cross-device-sync
npm run check:exam-flow
npm run check:account-retry
npm run check:notes
npm run check:bug-hunt
node --import ./scripts/extensionless-loader.mjs scripts/check-rank.mjs
npm run build
```

새 프론트엔드 검사는 실패 기록의 보관/복원, 재연결 전송, 계정별 자격 증명, 늦은 401, 저장 순서, 로그인/창 복귀 시 읽기, 요청 중 작성한 답 보존과 수동 실패 표시를 확인한다. 전공노트 검사에는 조회부터 끊긴 상황의 체크 보관과 재시도를 추가했다.

```bash
cd backend
bash gradlew test bootJar
```

`CrossDeviceProgressTest`는 두 개의 로그인 토큰으로 오래된 스냅샷을 보내도 서로 다른 문항과 노트 해제 기록이 보존되는지, 첫 저장 8개가 동시에 들어와도 모두 남는지, 잘못된 JSON이 기존 기록을 덮어쓰지 않는지 확인한다.

실제 로컬 PostgreSQL 17과 HTTP 서버에서도 동일 계정의 로그인 토큰 두 개로 첫 저장 8개를 동시에 보냈다. 두 세션이 같은 8개 문항을 읽고 오래된 스냅샷을 다시 보내도 8개가 유지됨을 확인했다. 운영 데이터는 사용하지 않았다.
