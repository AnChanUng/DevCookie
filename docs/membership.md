# 등급과 필기이론 접근

- 브론즈: 신규 방문자·신규 회원의 기본 등급.
- 실버: 반복 풀이를 제외하고 50문제 이상.
- 골드: 최초 적용 시 존재하는 회원 및 기존 방문자 기록에 부여하는 최소 등급.
- 다이아: 200문제 이상.
- 루비: 1,000문제 이상.

기존 회원·방문자는 풀이 수가 적어도 골드보다 내려가지 않는다. 기존 방문자의 자격은 브라우저의 방문자 ID로 유지된다. `MembershipRolloutService`는 최초 실행에서 `visitor_solved`, 닉네임 프로필, 기존 풀이 이벤트에 있는 방문자에게 골드를 부여하고 `membership_rollout`에 완료 표시를 남긴다. 재시작할 때 신규 방문자를 추가 승급하지 않는다. 기존 회원의 `base_tier`도 골드로 보존하며 새 가입은 브론즈를 명시한다. 기존 골드 방문자가 같은 브라우저에서 가입하면 골드를 이어받는다.

풀이 수는 문제은행별 문항을 한 번씩 세며, 같은 계정의 기기 수를 합산하지 않는다. 기존 순위 집계와 계정에 저장된 문항별 기록 중 큰 값을 사용한다. 학습 기록과 문제 수는 기존 서비스와 동일하게 클라이언트가 제출하는 방식이며, 이 등급은 별도의 서버 정답 검증 체계가 아니다.

`/api/v1/membership`이 현재 등급을 반환한다. 계정은 Bearer 토큰, 기존 비회원은 `X-Visitor-Id`를 사용한다. `/major` 계열 화면은 골드 이상을 요구한다. 이론 PDF는 프론트엔드 public 디렉터리에 두지 않고 서버의 `private-notes`에서 등급 검사 후 `/api/v1/theory/notes/{file}`로 제공한다. 이전 공개 PDF 파일은 새 프론트엔드 배포에서 제거된다.

닉네임은 1~20자이며 회원·비회원 사이에서도 중복을 막는다. 비교할 때 유니코드 NFKC, 소문자, 공백 정규화를 적용한다. `nickname_claims`의 고유 키로 동시 예약을 막고 계정/방문자 행을 잠가 변경 순서를 보존한다. 변경해도 사용자 ID·토큰·등급·풀이 기록은 유지된다. 회원은 변경한 닉네임으로 다음 로그인을 한다.

채팅 접속자 목록은 채팅창을 연 사람만 표시하고 30초마다 갱신하며, 갑자기 끊긴 접속자는 90초 후 만료한다. 공개 목록에는 방문자 ID 대신 임의의 참여자 핸들을 보낸다. 상대의 대결 신청 버튼은 주제별 문제 10개로 비공개 대결방을 만들고 해당 닉네임을 부른 참가 링크를 채팅에 전송한다.

검증: backend의 `bash gradlew test bootJar`; frontend의 `npm run check:membership`, `npm run check:lounge-chat`, `npm run check:account-retry`, `npm run check:exam-flow`, `npm run build`.

## 점진적인 세부 등급

표는 각 등급의 Ⅴ·Ⅳ·Ⅲ·Ⅱ·Ⅰ에 필요한 누적 문제 수다. 문제 수로 달성한 등급과 시험으로 획득한 최소 등급 중 높은 쪽을 적용한다.

| 등급 | Ⅴ | Ⅳ | Ⅲ | Ⅱ | Ⅰ |
|---|---:|---:|---:|---:|---:|
| 브론즈 | 0 | 5 | 12 | 25 | 45 |
| 실버 | 50 | 60 | 80 | 120 | 180 |
| 골드 | 0 | 20 | 50 | 100 | 170 |
| 다이아 | 200 | 250 | 350 | 550 | 850 |
| 루비 | 1,000 | 1,100 | 1,300 | 1,700 | 2,300 |

동일 등급 안에서는 승급에 필요한 추가 풀이 수가 증가한다. 골드는 +20·30·50·70문제이며 기존 200문제 다이아, 1,000문제 루비 기준은 유지한다. 골드 자격이 없는 신규 회원은 실버 다음에 다이아로 올라가며 골드는 기존 교육생의 자격이다. solved.ac 공식 아이콘의 단계별 SVG를 사용한다.

## 교육생 명부와 개인정보 배지

`cohort_memberships`는 프로그램(SSAFY), 기수(16), 캠퍼스(대전), 반(4), 적용 시각과 고정 사용자/방문자 ID를 저장한다. `CohortRolloutService`는 기존 골드 기본 자격을 가진 회원과 방문자를 한 번만 저장하고 `membership_rollout.id=2`를 기록한다. 이미 다이아·루비로 승급한 기존 골드도 포함한다. 신규 회원을 교육생으로 자동 편입하지 않는다. 닉네임/티어 변화로 명부를 덮어쓰지 않는다. 기존 방문자가 가입하면 배지를 계정에 연결한다.

배지는 본인 설정의 개인정보 영역에서만 표시한다. `/api/v1/profile/badges`는 Bearer 계정 또는 현재 브라우저의 `X-Visitor-Id`만 조회하며 타인 지정 매개변수를 받지 않는다. 회원에 연결된 방문자 배지는 비로그인 상태에서 조회하지 않는다. 응답은 `no-store`이며 DB 행/식별자/적용 시각을 노출하지 않는다. 공개 순위·채팅·일반 membership 응답에는 기수·캠퍼스·반을 포함하지 않는다. 운영 DB의 실제 명부 생성은 새 백엔드 시작 시 실행된다.

## 승급 시험

홈 대결 버튼 오른쪽의 시험(`/promotion-exam`)은 기존 문제에서 운영체제·네트워크·데이터베이스·컴퓨터구조 각 6문제와 C·Java·Python 각 2문제, 총 30문제를 서버에서 무작위 출제한다. 동일 지문/보기의 중복을 제거한 문제 풀을 사용하며 C#/C++는 제외한다. 원본 문제은행 수정 후 프론트엔드 디렉터리에서 `node --import ./scripts/extensionless-loader.mjs scripts/export-promotion-bank.mjs`로 백엔드 문제 스냅샷을 갱신한다. `--check`로 동기화 여부를 검사한다.

`promotion_attempts`에 응시자·문항 스냅샷·결과를 저장하고 서버가 답안 30개를 채점한다. 출제 응답에는 정답/해설을 포함하지 않는다. 95점 이상은 29/30(96.7점), 28/30은 93.3점으로 불합격이다. 합격하면 현재의 다음 한 단계로 승급하여 `tier_awards`에 최소 단계를 저장한다. 같은 시험 재제출은 원래 결과를 반환하고 다시 승급하지 않는다. 응시 기록과 승급 행을 잠가 중복 제출을 직렬 처리한다. 새 시험 합격은 다시 한 단계 승급할 수 있고 루비 Ⅰ이 상한이다. 풀이 수를 임의로 늘리지 않으며, 방문자 승급도 가입 시 계정으로 이어진다. 시험 결과를 제출한 후에만 해설을 표시한다. 브라우저의 진행 ID/답안과 서버의 시험 기록으로 새로고침 후 이어 풀 수 있다.
